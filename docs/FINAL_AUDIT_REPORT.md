# MedAlignFlywheel · 最终技术审计报告

> 本轮目标：**不再增加功能、不做全参微调、不美化 UI**，只解决影响技术面试可信度的三个问题。
> 全文数字均来自本地真实运行；凡未验证者一律明确标注，不以推断填充结论。

---

## 摘要：三个问题的结论

| 问题 | 结论 |
|---|---|
| 模型实现保真度 | 词表/分词器/特殊 token/预处理/池化/位置编码**已逐项与官方产物对照一致**；但**全塔前向的逐向量等价性本机无法验证（BLOCKED）**，只声称"无已知计算差异"，不声称"完全等价"，并提供一键验证脚本 |
| 严格独立 Holdout | 旧 55 条**已被污染**（14/55 与难例重叠），已废弃；新建 **1000 条从未参与开发的独立测试集**（与开发集零重叠），冻结配置后**只评价一次** |
| 数据飞轮价值 | A/B 相同、困难优先下降、长尾弱**三个现象的原因均已查清并量化**；但**"数据选择带来训练增益"仍属未证明**，不强行追求正向提升 |

## 任务一 · 模型实现保真度审计

### 1.1 审计了什么（不再依赖间接推断）

此前曾用"低 UNK 率 + 权重加载成功 + 高 AUROC"间接背书，**这些都不能证明等价**。本轮改为逐项可验证对照：

| 编号 | 审计项 | 方法 | 结果 |
|---|---|---|---|
| V1 | 词表来源 | 与 HF 官方 `vocab.txt` 做 SHA256 比对 | **字节级一致**（`7b366519…`），且行数同为 28895 |
| V2 | Token ID 映射 | 官方 `tokenizer.json` 词表与本地逐位比对 | **0 处不一致** |
| V3 | 特殊 Token | 查表 | **[PAD]=0 / [UNK]=1 / [CLS]=2 / [SEP]=3 / [MASK]=4**，与官方一致 |
| V4 | 大小写 | 比对官方 `tokenizer_config.json` | `do_lower_case=True`，实现一致 |
| V5 | HF 额外行为 | 量化中文切分与去重重音对本语料的影响 | 含中文 **0** 条；去重音仅改变 **1/990**（0.1%）条的分词 |
| V6 | token_type | 检查 checkpoint 键 + **消融验证** | checkpoint 含 `token_type_embeddings`，置零后输出变化 ⇒ **确实参与前向**，与 HF 默认 `token_type_ids=0` 一致 |
| V7 | 位置编码 | 比对 cfg 与 checkpoint 形状 | `max_position=512` ≥ `context_length=256`，checkpoint 形状 `[512,768]` 一致 |
| V8 | 预处理 | 与官方 `preprocess_cfg` 比对（1e-6 容差，避免 float32 舍入误判） | mean/std **一致**；流程=短边缩放→中心裁剪→/255→归一化→CHW |
| V9 | 池化 | 比对配置 + 检查权重有无额外 pooler | `cls_last_hidden_state_pooler`，实现取最后一层 CLS，权重**无**额外 pooler 参数，一致 |
| V10 | 加载与确定性 | 严格加载 + 参数量 + 两次前向 | 195,902,721 参数，前向确定性 **maxdiff=0.0** |

> **重要澄清**：checkpoint 文本 embedding 为 30522 行，而官方词表仅 28895 条——这**不是**本地词表被截断（V1 已证字节级一致），而是模型发布时 embedding 矩阵大于随附词表，多出的 1627 行从未被分词器使用。

### 1.2 仍未验证的边界（明确记录，不掩饰）

| 编号 | 未验证项 | 原因 / 处置 |
|---|---|---|
| U1 | **全塔前向与官方的逐向量数值等价性** | 本机两种方案均失败：medalign(torch1.13+cu116) `import open_clip` 段错误；refclip(torch2.x CPU) `c10.dll` 初始化失败。已停止继续安装依赖，记为 BLOCKED |
| U2 | PIL bicubic 与 torchvision bicubic 的亚像素差异 | 未实测量化 |
| U3 | 自实现 Self-Attention / `F.gelu` 与 HF 的中间数值一致性 | 结构一致（均为精确 erf GELU），数值未实测 |
| U4 | 官方分词器在极端输入下的运行期行为 | V1–V5 为文件级/行为级验证，非逐样本运行期对照 |

### 1.3 可移植验证脚本

`scripts/reference_compare_openclip.py`——在**装了 open_clip 的机器上**一键完成对照：

```bash
pip install torch open_clip_torch timm transformers pillow numpy
python scripts/reference_compare_openclip.py \
  --weights-dir data/external/models/biomedclip \
  --manifest data/metadata/clean_manifest.jsonl \
  --images-dir data/raw/images --n 32 \
  --out reports/reference_compare_openclip.json
```

比对内容：token id 逐位一致率、图像/文本 embedding 的 `max_abs_diff` 与平均余弦、检索 Top-1 一致率；任一不一致则退出码 1 并标注差异。**在它跑出 PASS 之前，本项目不声称与官方等价。**

## 任务二 · 严格独立 Holdout 审计

### 2.1 旧 55 条 holdout 的污染审计（结论：不合格，已废弃）

| 维度 | 是否参与 | 证据 |
|---|---|---|
| 旧版 P3 困难样本挖掘 | **是** | **14/55** 与 `hard_cases.jsonl` 重叠 |
| 旧版 P3 难负例构造 | **是** | **55/55** 出现在 `hard_negatives.jsonl` 候选池 |
| P4 对齐头训练 | 否 | P4 诊断的 `pool_rule` 明确为"train 剔除预注册 holdout(55)" |
| 数据选择 / 阈值调整 | 间接是 | 质量阈值与选择策略在 round 1 基于完整 train（含这 55 条）确定 |

> **处置**：这 55 条**不再称为"未见数据"**，已从 holdout 用途中废弃；相关事实已写入自动化测试（测试项 `old_holdout_contamination_recorded` 断言重叠>0，防止日后误用）。

### 2.2 新建独立测试集

- 来源：**ROCOv2 test split 中从未被本项目摄取过的行**（HF datasets-server `/rows`，offset 2000 起）。
- 去重规则：按 `image_id` 与**图像 SHA256 双重去重**，排除与既有 1000 条开发样本重复者。
- 规模：**1000 条**，与开发集 `sample_id` 重叠 **0**（自动化测试断言）。
- 图像独立存放于 `data/raw/images_holdoutv2/`，不混入开发集目录。

### 2.3 纪律：先冻结、后评价，且只评价一次

`configs/frozen_final_eval.json` 在**计算任何指标之前**落盘，记录候选规模、指标、种子、权重 SHA256、清单 SHA256、近重复阈值、候选排序规则。评价脚本在结果文件已存在时**拒绝重算**（除非显式 `--force`）。

> 过程中曾因 `image_relpath` 路径解析错误导致 1000 张图全部读取失败（向量全零，R@1≈0.005）。已加入**安全护栏**：失败率 >5% 直接中止且不落盘，避免产出垃圾指标。修复后重跑 `failed=0`。

### 2.4 最终真实指标（独立测试集，仅此一次）

| 候选规模 | I2T R@1 | 95% CI | R@5 | R@10 | MRR | T2I R@1 | AUROC |
|---|---|---|---|---|---|---|---|
| 200 | **0.810** | [0.755, 0.860] | 0.970 | 0.995 | 0.883 | 0.810 | 0.9976 |
| 500 | 0.666 | [0.626, 0.708] | 0.924 | 0.972 | 0.782 | 0.656 | 0.9976 |
| 1000 | 0.587 | [0.556, 0.619] | 0.870 | 0.926 | 0.712 | 0.590 | 0.9970 |

> 与原开发期 test 结果（200→0.805、500→0.665、1000→0.590）**高度一致**，说明流水线与指标口径稳定，未因换数据而漂移。

### 2.5 限制（必须同时说明）

1. **来源重叠**：ROCOv2 公开接口**不暴露来源论文 ID**，无法按论文分组；只能按近重复簇分组。本集内近重复图像对 4、近相同图注对 172、易混淆样本 160、与开发集跨集近重复 2——同一论文的多子图共享相似图注，会使任务偏易。
2. **多对多正确配对**：图文并非严格一对一。近相同图注的多个图像在语义上都可能"正确"，R@1 会把语义等价候选计为错误，属指标口径的**固有保守偏差**（真实性能可能略高于报告值）。
3. **预训练数据潜在重叠**：BiomedCLIP 在 **PMC-15M** 上预训练，而 ROCOv2 图像来自 **PMC Open Access 子集**，二者存在**实质重叠可能**。因此高 R@1 **不能排除部分来自预训练记忆**，不能解读为"纯净的零样本泛化能力"。

## 任务三 · 数据飞轮的实际价值

### 3.1 三个现象的原因（均已查清并量化）

| 现象 | 原因 | 证据 |
|---|---|---|
| 质量筛选 A 与 B 完全相同 | `clean_manifest` 本身已是 P1 质量门后的保留集（1000→990，仅拒 10），B 的附加过滤在已清洁子集上近乎空操作 | 探针：A/B 子集内 R@1 均为 0.8083（完全一致） |
| 困难样本优先反而训练更差 | 困难子集**确实更难**（正例相似度更低、子集内 R@1 更低）；但在**冻结编码器 + 仅 200 样本**下，模型没有足够容量从难例中学到泛化规律，反而放大对少量难例的过拟合 | 探针：C 子集 R@1=0.650 < A 的 0.808，pos_sim 0.438 < 0.449；P4 训练结果 C 最差（0.507 < 基线 0.805） |
| 长尾覆盖增益弱 | train 池中 singleton（仅出现一次）概念**只有 1 个**，长尾优先能机械覆盖它，但绝对增益微不足道，且牺牲模态/概念广度（覆盖 8→6） | 长尾指标：D 的 singleton 覆盖 1.0 vs A 的 0.0，但 pool 内 singleton 总数=1 |

> **方法学诚实说明**：探针中"子集内 R@1"与困难样本的定义（正例排名>1）相关，C 子集 R@1 更低**部分是定义的必然结果**，属描述性证据，不能单独作为因果证据；需与 P4 训练结果合并解读。

### 3.2 已证明 / 未证明清单

**已证明（有客观证据）**
- 质量算子能真实识别缺陷：合成缺陷 **5/5** 自动识别、**8/8** 清洁样本 0 假阳性；
- 模型困难案例已被真实挖掘并分类：229 条（模型排序错误 214 / 边界正例 15），**全部为共享概念**、**全部需人工复核**；
- 困难负例三重校验产出 1,218 条确定负例（来源非近重复 / 概念不相交 / 语义不重叠）；
- 数据选择能显著改变子集结构（C 把困难样本占比 27%→83%），但**结构改变 ≠ 训练收益**；
- 冻结编码器 + 200 样本训小对齐头会**过拟合拖累**检索（0.81→0.57）。

**未证明（如实标注，不强行追求正向提升）**
- ❌ 任何"数据选择带来训练增益"的说法——P4 四种策略**全部低于基线**，增益在本规模与冻结设置下不可见；需全参微调或更大数据才能检验；
- ❌ 229 条难例中**没有一条**被确认为"医学错配"——`risk_false_positive` 仅表示模型把高相似负例排在正例之前，**不等同于已确诊错配**，须人工复核后才成立；
- ❌ 长尾选择的实际训练收益（受 singleton 数量极少限制）；
- ❌ 自包含前向与官方实现的逐向量等价性（U1，BLOCKED）。

## 能力边界：已证明 vs 仍属研究探索

| 类别 | 内容 |
|---|---|
| **已证明的技术能力** | 合规数据摄取与跨集近重复泄漏检测；可审计的六维质量算子与血缘（含合成缺陷验证）；真实 BiomedCLIP 跨模态检索评测（含候选规模对照、分层分析、AUROC 与 bootstrap CI）；难例/难负例挖掘与分类；冻结配置与一次性最终评价的工程纪律；评测链路 bug 的定位与修复能力 |
| **仍属研究探索（未获证实）** | 数据选择策略的训练收益；困难/长尾样本的实际价值；自包含前向与官方的严格等价性；在"预训练数据可能重叠"前提下模型真实泛化能力的纯净度量 |
| **预训练模型能力 vs 本项目贡献** | 0.81 的跨模态对齐来自 **BiomedCLIP 预训练**；本项目的工程贡献是：数据合规与泄漏防护、质量与血缘体系、困难样本发现与分类、严格的实验纪律与诚实的边界结论。**不把预训练能力计入本项目成果。** |
