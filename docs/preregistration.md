# 预注册未见数据协议（P0-5）

## 目的

本项目的 `test` 切分（200 条）已被反复检查并用于最终报告。为遵守以下纪律：

> **后续任何参数调整、数据选择、对齐头训练，只能使用 `train`（开发子集）与 `validation`；**
> **"最终验证"必须使用一套此前从未被任何步骤见过的封存数据。**

我们从 `train` 中确定性封存一个 holdout 子集，作为"未见过的数据"。

## 封存规则（确定性、可复现）

- 取 `train` 全量 `sample_id` 排序后，按 `SHA1(sample_id) mod 10 == 0` 入选（约 10%）。
- 该规则与任何随机种子无关，可由 `scripts/run_p0_holdout_seal.py` 完全复现。
- 本次封存结果：**55 / 592** 条。

## 封存产物

| 文件 | 内容 |
|------|------|
| `data/metadata/holdout_sealed.jsonl` | 55 条 holdout 的 `sample_id` 与角色标记 |
| `data/metadata/holdout_seal.json` | 规则、数量、排除清单、SHA256 指纹、时间戳 |

### 指纹（防替换）

- `id_list_sha256`：55 个 ID 排序拼接后的 SHA256 —— 防止 ID 列表被事后篡改。
- `holdout_embeddings_sha256`：holdout 的图文向量拼接后的 SHA256 —— 防止向量被悄悄替换。

## 使用纪律（强制）

1. **禁止**在以下任何环节使用 holdout：
   - 超参数搜索（含学习率、温度、对齐头宽度）
   - 数据选择策略 A/B/C/D 的构建与比较
   - 对齐头（P4）训练、早停、模型挑选
   - 任何"看指标后改方案"的调参
2. holdout **仅在所有方法冻结后、做最终验证时整体打开一次**；打开动作本身需在实验日志中单独记录（含打开时间、所用指标、结论）。
3. 若因资源/时间限制未能打开 holdout 做最终验证，则如实说明"holdout 已封存未启用"，**不得**用 `test` 数字冒充 holdout 结论。

## 与现有切分的关系

| 切分 | 规模 | 角色 |
|------|------|------|
| train（开发子集，剔除 holdout） | 537 | 训练 / 调参 |
| validation | 198 | 开发集 / 调参 |
| test | 200 | 已冻结，用于最终报告 |
| **holdout（预注册）** | **55** | **未启用，最终验证时打开** |

> 说明：holdout 物理上来自 `train`，但因其从任何调参/选择/训练中**完全排除**，对模型选择与报告而言等价于"未见过的数据"。这是一种标准 ML 实践（train/val/test 之外再设密封 holdout），在此明确记录以保证可审计。
