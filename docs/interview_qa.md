# 面试题与答案（MedAlignFlywheel 相关，≥20 题）

> 围绕"多模态数据对齐 / 质量评估 / 数据飞轮 / CLIP / ROCOv2 / 检索指标"设计，供求职面试准备。

## 一、数据合规与摄取

**Q1. 为什么选 ROCOv2？它的许可边界是什么？**
A. ROCOv2 是公开的医学影像+图注+CUI 数据集，适合做图文对齐基准；许可为 CC BY-NC-SA 4.0（来源图像来自 PMC Open Access Subset）。边界：仅本地评估、不对外重新分发整套图像；且必须明确"图注来自开放获取论文图注，不是医院诊断报告"，不能把数据性质说错。

**Q2. 你是怎么避免下载完整 18GB 数据的？**
A. 用 HuggingFace datasets-server 的 `/rows` API 做行级分块随机抽样（train 20 块×30、val/test 8 块×25，种子固定），只拉取 1,000 行对应图像，配合限速、缓存与断点续跑；同时记录每条的 source URL 与 SHA256。

**Q3. 什么是跨切分近重复泄漏？你如何检测与处理？**
A. 同一张图或几乎相同的图注若同时出现在 train 与 test，会让 test 指标虚高。我用 pHash/dHash 距离 + 图注词面 Jaccard/containment 判定近重复；曾用并查集传递闭包导致"链式误合并"误报 71 条跨集泄漏，后改为"星型聚类、成员必须与 leader 直接满足阈值"，假泄漏归零，最终只剔除 10 条真实不合格样本。

## 二、质量评估

**Q4. 你的"六大质量算子"指什么？**
A. 图像完整性（损坏/尺寸/灰度统计）、文本质量（长度、数字比、非 ASCII 比、模板化）、图文配对完整性（图注是否对应图像）、CUI 质量（概念格式与覆盖）、近重复（pHash+文本相似）、数据血缘（SHA256/来源/算子版本/拒绝原因）。输出 raw/clean/rejected 与原因统计。

**Q5. 图注"模板化/重复"为什么是问题？**
A. ROCOv2 图注来自论文图注，措辞高度同质（如"Chest X-ray showed…"）。模板化会降低信息量、放大近重复、让检索变难；我们用 caption_top_token_ratio、Jaccard 等量化并标记，但不强行删除——它反映真实分布，是飞轮要处理的目标而非错误。

**Q6. 数据血缘（lineage）在实战中有什么用？**
A. 每条样本记录来源 URL、SHA256、各算子结论与版本、拒绝/警告码。一旦上游数据或算子变更，可精确回溯哪些样本受影响、哪些指标要重算，是数据可审计、可复现的基础。

## 三、CLIP / BiomedCLIP

**Q7. 为什么不用官方 open_clip 而是自包含实现？**
A. 本机 torch 锁在 1.13.1+cu116，import open_clip 会 segfault；transformers/timm 新版要 torch≥2。因此按官方 config 用 torch 原生模块重建 ViT-B/16 + PubMedBERT，并加三道闸：strict 零缺失零多余加载、SHA256 指纹、真实数据行为校验。

**Q8. 你是怎么保证自包含前向"没搭错"的？**
A. 两处关键：① 视觉塔必须是预归一化 ViT（`x=x+attn(norm1); x=x+mlp(norm2)`），我曾把 norm2 错用在注意力前，导致 I2T R@1 掉到 0.03，修正后才回到 0.8；② 权重 strict 加载 + 指纹；③ 在真实 ROCOv2 上算检索指标，若结构错会退化到随机，可反推。

**Q9. CLIP 的对比学习目标是什么？logit_scale 起什么作用？**
A. InfoNCE：同批内"正图文对"相似度最大、与其他负对最小。logit_scale 是可学习温度，把余弦相似度缩放到合适量级；检索排名对它的单调缩放不敏感，但零样本分类分数依赖它。

**Q10. 图像和文本塔输出要做 L2 归一化吗？为什么？**
A. 检索时通常对两塔输出各自 L2 归一化再点积即得余弦相似度，使比较与尺度无关。BiomedCLIP 两投影头尺度不同（原始范数差数倍），归一化是必须步骤。

## 四、检索评测

**Q11. R@K、MRR、AUROC 各衡量什么？**
A. R@K：正确项进入前 K 的比例（召回）；MRR：正确项排名倒数的均值（排序质量）；AUROC：正例相似度高于负例的概率（整体可分性，与候选池大小无关）。

**Q12. 你的 AUROC 初版出现 <0.5，是什么 bug？**
A. `auroc_rank_based` 用 `searchsorted` 时统计成了"负例>正例"的配对占比，返回的是 1−AUROC；修正为统计"负例<正例"后，AUROC 从 0.38 变回 0.997。这说明指标实现也要被真实数据校验。

**Q13. 为什么负例要"净化"（排除模糊负例）？**
A. ROCOv2 同一论文多子图常共享极相近图注，把这种"非配对但语义近"的 pair 当负例会系统性高估 AUROC。我用"图注 containment 过高 或 图像 pHash 距离过小"判定模糊 pair，排除 146 个，并如实公开数量，只算剩余 clean 负例的 AUROC。

**Q14. 冻结 test 集纪律为什么重要？**
A. test 只能用于报告最终指标，不能参与 P1 调参、P3 选择、P4 训练，否则污染基准。本项目 train/val 用于挖掘与选择，test 全链路隔离。

**Q15. I2T 和 T2I 哪个更难？你的结果怎样？**
A. 取决于候选池与文本同质度。本项目 test 上 T2I R@1=0.810 略高于 I2T 0.805，二者接近；R@10 均达 0.99，说明"是否在候选内"已基本解决，瓶颈在 Top-1 精确区分同质图注。

## 五、数据飞轮

**Q16. 什么是"难例挖掘"？你挖了哪两类？**
A. 从模型错误里找值得人工复核的样本：① hard_positive（配对正确但模型排名低，训练价值高）；② risk_false_positive（某错配得分高于正例，可能是数据风险）。本项目挖出 229 例，全部带空白复核字段，不擅自宣称数据缺陷。

**Q17. 难负例构造为什么要做三重校验？**
A. 一个 pair 当且仅当通过"来源非近重复 / 概念不相交 / 语义不重叠"三关，才能标为"确定负例"，否则标 needs_review。否则会把疑似正例（近重复图/共享概念/同义图注）当负例误导训练。本项目 4,736 候选中 1,218 个确定负例。

**Q18. A/B/C/D 四种选择策略差别在哪？C 和 D 的权衡是什么？**
A. A 随机；B 质量过滤后随机（本清洁子集与 A 完全一致）；C 质量+困难优先；D 质量+长尾概念优先。C 把困难样本占比从 27%→83%，D 模态覆盖从 8→6（长尾优先的代价）。这些都是数据侧描述，模型收益须由 P4 对照训练给出。

**Q19. 飞轮"闭环"体现在哪？**
A. P3 选出的高质量/高价值子集回流驱动下一轮数据生产（更多少数概念采集、针对难例补标注/校验），再回到 P1 评估——形成"评估→选择→生产→再评估"的闭环。

## 六、工程与方法

**Q20. Bootstrap 置信区间怎么算的？为什么不用单次点估计？**
A. 对每条样本的命中指示做有放回重采样（种子固定）得到分布，取 2.5%/97.5% 分位。因为子集仅 200/990，点估计波动大，区间能诚实表达不确定性。

**Q21. 你如何保证"不伪造"？**
A. 相似度全部来自真实 GPU 前向；未运行的模块（P4）标 NOT_TESTED；公开两处评测 bug 的更正；任何人工标签（难例复核）留空待填，不臆造结论。

**Q22. 如果算力更充足，P4 你会怎么设计对照实验？**
A. 冻结 BiomedCLIP 编码器，仅训练一个小对齐头（如双塔各自的线性/浅 MLP 投影，或 cross-attention head），用 A/B/C/D 各 200 条子集在 frozen test 上对比同一训练预算下的检索/零样本指标，报告差异与显著性；记录每个策略的 seed 与超参，保证可复现。

**Q23. 这个项目和"单纯训练一个 CLIP"的区别？**
A. 重点不是刷模型 SOTA，而是**数据侧工程能力**：合规、质量、泄漏、飞轮与选择策略——这正是"全模态大模型数据"岗位的核心：决定喂给模型的数据到底好不好、值不值得。

**Q24. 如果让你把这套方法迁移到中文医疗多模态数据，难点在哪？**
A. ① 中文图注需要中文分词/医学实体对齐（CUI 多为英文 UMLS）；② 国内合规（隐私/许可）更严格，需做 PHI 脱敏；③ 中文医学图文对公开资源稀缺，飞轮的"困难/长尾"定义要随语种重标定。我会复用质量算子框架，替换分词与概念对齐模块、加入脱敏算子。

## 五、深挖：模型可信度与实验纪律（本轮新增）

**Q25. 你说自实现前向"没搭错"，但有没有和官方 open_clip 跑过逐向量对比？**
A. 如实说明：本机两种方案都失败了——medalign 环境（torch 1.13+cu116）`import open_clip` 直接段错误；新建干净 venv（torch 2.x CPU）则 `c10.dll` 初始化失败（系统级库问题，非代码）。因此"实时官方前向逐向量对比"记为 **BLOCKED**，没有伪造该对比。我改用替代证据链：① 与官方 `open_clip_config.json` 的架构规格逐项比对（embed_dim=512、vit_base_patch16_224、视觉投影 768→512 线性、文本 mlp 768→640→512、cls 池化、context_length=256、预处理均值/标准差）**全部匹配**；② 权重 strict(zero-missing/zero-unexpected) 加载 + SHA256 指纹；③ 前向**确定性**（同输入两次编码差=0.0）；④ 词表保真：checkpoint 文本 embedding 为 30522 行，我的 vocab.txt 28895 行，但全部图注 token 的 UNK 率仅 **0.035%**；⑤ 检索 AUROC≈0.997 佐证对齐真实存在。

**Q26. I2T R@1=80.5% 是不是因为"候选只有 200 个"显得高？**
A. 不是。我在 200/500/1000 三种候选规模下都重算了：I2T R@1 = 0.805 / 0.665 / 0.590，随候选数放大自然下降；但 **AUROC 始终 ≈0.997**（正负例可分性不随候选数衰减）。所以 80.5% 是 200 候选口径的真实值，不是缩小候选的假象。

**Q27. 同源论文、重复图像、相似图注会不会让检索任务"太容易"？**
A. 我在 200 test 池内量化了：近重复图像对仅 2、近相同图注对 27、共享概念混淆查询 36。剔除 36 个最易混淆的查询后 R@1 反而 **0.811**（不降），说明这些样本并没有人为变易任务。不过 ROCOv2 同论文多子图的特性确实让"共享概念"成为主要困难来源——这在我的 229 难例中占 100%（全部为 shared concept），也是飞轮要处理的核心对象。

**Q28. P4 你最初说 R@1=0.005，后来又说 0.57，到底哪次是真的？两次的根因分别是什么？**
A. 第一次 0.005 是 bug：我把"近恒等初始化"错写成输出层零初始化，导致对齐头前向恒为 0，彻底破坏原有对齐。修正为残差结构 `out = x + mlp(x)`、零初始化即精确恒等后，R@1 回到 0.57——这才是真实值。真实结论是：在已接近天花板的冻结 BiomedCLIP 上，仅用 200 样本训练小对齐头会**过拟合并拖累**检索（train R@1→≈1.0，但 test 从 0.81 跌到 0.57），且四策略（含困难/长尾优先）均低于基线。这是诚实的边界结论，不是"选择提升"。

**Q29. 你如何保证调参没有"偷看" test？**
A. 两层纪律：① test 集冻结，只用于最终评测，不参与 P1 调参、P3 挖掘/选择、P4 训练；② 我额外**预注册了 55/592 条 train 样本为未见 holdout**（记录 ID 与向量 SHA256 防替换），后续任何参数/选择调整只用 train/validation，holdout 仅用于最终验证。这样即使 train 上反复试验，也有一块从未接触的数据做独立校验。

**Q30. 你声称的"数据质量算子有效"有没有被测量过？A 策略和 B 策略为什么完全一样？**
A. 两个独立证据：① 在 train 上构造可核验的合成缺陷（缺失图注、空图注、占位符 nan、重复词、纯数字、同图复用），真实算子做到 **5/5 自动识别、8/8 清洁样本 0 假阳性**，重复图像还被正确聚成簇；② A==B 的根因是 `clean_manifest` 本身就是 P1 质量门后的产出（1000→990 仅拒 10 条），所以 B 的附加过滤在已清洁子集上几乎是空操作——这恰恰说明质量过滤的价值在"摄取后第一时间门禁"，而非事后在干净集上再筛。

**Q31. 229 条难例里，有多少是"确定错的医学错配"？**
A. **零条被确定为错配**。它们分两类：模型排序错误 214（risk_false_positive：模型把某负例排在正例前）、边界正例 15（正例未排第 1 但正确）。全部 229 条都带 `needs_human_review` 且全部为共享概念（图文配对歧义普遍存在）。关键边界：未人工审核的 `risk_false_positive` 只表示"模型检索排序把高相似负例置于正例之前"，**不等同于已确诊的医学错配**；真正的错配须经人工复核字段确认，我绝不用它冒充确定错误。

**Q32. 长尾选择策略 D 真的能覆盖更多罕见概念吗？**
A. 我改进了指标，不再只用"总 CUI 数"，而是算**单例（singleton）CUI 的真实覆盖**。结果：D（长尾优先）的 singleton 覆盖 = 1.0，A（随机）= 0.0；但要诚实说明——train 池里 singleton CUI 只有 **1 个**（概念分布极偏），所以 D 确实机械地保证了那 1 个罕见概念被选中，而随机漏掉。机制有效，但绝对增益在本数据集上因稀缺概念太少而有限。这正是"真实数据质量评估"该给出的边界，而非夸大。

**Q33. 你的演示页里的真实图像和检索结果能让人信服吗？**
A. `reports/index.html` 第 5 节放了 4 个可复核案例（正确匹配 / 模型失败 / 质量异常 / 医学歧义），每个都含查询图像缩略图、Top-5 检索结果、真实相似度与正确配对位置，图像来自真实前向推理、未做任何修饰，并保留 ROCOv2（CC BY-NC-SA 4.0）出处与许可。让不读代码的人也能理解项目到底解决了什么问题。

**Q34. 预训练模型的能力和你的工程贡献，你怎么区分？**
A. 0.81 的跨模态对齐来自 BiomedCLIP 预训练，这是它的能力，不是我的。我的**新增工程贡献**是：合规数据摄取与跨集泄漏检查、可溯源的质量算子、难例/难负例挖掘与三重校验、四种数据选择策略的可核验对比，以及"冻结编码器下 200 样本对齐头无法增益"的诚实边界结论。我严格区分"模型能做"和"我做了什么"，绝不把预训练能力算成自己的成果。

## 六、最终验收轮：可信度深挖（新增）

**Q35. 你说预注册了 55 条"未见数据"，为什么后来又废弃了？**
A. 因为审计发现它**根本不是未见数据**：14/55 与旧版 P3 困难样本挖掘结果重叠，55/55 全部出现在难负例候选池里，且质量阈值与选择策略当时就是基于含这 55 条的完整 train 确定的。唯一干净的是 P4 训练（明确剔除了它们），但那不足以挽救。所以我把这 55 条废弃，改用**从未被本项目摄取过的 1000 条公开 ROCOv2 样本**重建独立测试集（与开发集 sample_id 重叠 0，自动化断言）。这条我写进了测试，防止日后误用。教训是：**"封存"不等于"未见"，必须回溯所有历史实验是否消费过它。**

**Q36. 你的自包含前向到底能不能算"与官方等价"？**
A. **不能这样声称。**我把它拆成"已验证"和"未验证"两部分：已验证的是词表（与官方 vocab.txt **字节级 SHA256 一致**）、Token ID 映射（官方 tokenizer.json 顺序 **0 处不一致**）、特殊 token（[PAD]=0/[UNK]=1/[CLS]=2/[SEP]=3）、预处理 mean/std、池化方式（最后一层 CLS）、位置编码、以及 token_type 确实参与前向（消融验证）。**未验证**的是全塔前向的逐向量数值等价性——本机跑不了 open_clip（两种方案都失败）。所以我提供 `scripts/reference_compare_openclip.py`：在有 open_clip 的机器上跑一次，比对 token id、两侧 embedding 的 max_abs_diff 与 Top-1 一致率。**在它 PASS 之前，我只说"无已知计算差异"，不说"等价"。**

**Q37. 官方词表是 28895 条，但 checkpoint 的 embedding 有 30522 行，是不是你的词表被截断了？**
A. 不是。我下载了 HF 官方 vocab.txt 做 SHA256 比对，**字节级完全一致**，行数同样 28895。所以是模型发布时 embedding 矩阵（30522）大于随附词表（28895），多出的 1627 行**从未被分词器使用**。这不是缺陷，但我之前只靠"UNK 率低"推断是不够的——本轮用文件级比对才真正定性。

**Q38. 最终指标是多少？凭什么相信它没被"偷看"？**
A. 独立测试集（1000 条全新样本）上：200 候选 I2T R@1=**0.810**（95% CI 0.755–0.860）、R@5=0.970、MRR=0.883、T2I=0.810、AUROC=0.9976；500→0.666、1000→0.587，AUROC 始终≈0.997。可信性来自三点：① 数据从未参与任何开发（双重去重 + 零重叠断言）；② **配置在评价前冻结**（权重/清单 SHA256 都写进 frozen config），且脚本拒绝重复评价；③ 过程中曾因路径 bug 导致 1000 张图全读失败，我加了"失败率>5% 直接中止"的护栏并重跑（failed=0），避免产出垃圾指标。

**Q39. 这个 0.81 有没有可能是"背答案"？**
A. **非常可能，我主动披露这条限制**：BiomedCLIP 在 PMC-15M 上预训练，而 ROCOv2 图像来自 PMC Open Access 子集，两者存在实质重叠可能。所以 0.81 **不能排除部分来自预训练记忆**，不能解读为"纯净的零样本泛化能力"。另外两条限制是：ROCOv2 不暴露来源论文 ID（只能按近重复簇分组，本集内易混淆样本 160 条）；图文并非严格一对一（近相同图注的多个图像语义上都可能正确，R@1 是保守口径）。

**Q40. 数据飞轮到底有没有价值？你为什么没做出正向提升？**
A. 三部分讲清楚：**已证明**——质量算子有效（5/5 识别、0 假阳性）、困难案例被真实发现并分类（229 条，全部共享概念）、难负例三重校验产出 1218 条确定负例、选择策略能显著改变子集结构（困难占比 27%→83%）。**未证明**——任何"选择带来训练增益"的说法：P4 四种策略**全部低于**冻结基线（0.578/0.578/0.507/0.527 vs 0.805），因为冻结编码器 + 仅 200 样本没有容量从难例中学习，反而过拟合；且长尾 singleton 概念在本池里只有 1 个，绝对增益微不足道。所以我不包装成"提升"，而是给出边界结论：**需全参微调或更大数据才能检验**。这本身就是数据岗位要交付的判断。

**Q41. 229 条难例里有没有"确诊的错配"？**
A. **一条都没有。**它们分两类：模型排序错误 214（模型把某负例排在正例前）、边界正例 15（正例未排第 1）。关键边界：`risk_false_positive` 只表示**检索排序关系**，不等同于医学上的错配；全部需人工复核字段确认后才成立。我绝不用未审核样本冒充确定错误——这是数据质量工作的底线。

**Q42. 演示包能独立打开吗？图片许可怎么处理？**
A. `demo_package/index.html` 是**单文件自包含**（1.25 MB，图片以 base64 内嵌），双击即可在任何机器离线打开，不依赖 assets 目录或本机绝对路径。图片来自 ROCOv2（CC BY-NC-SA 4.0），页面保留数据来源、DOI、许可与非商业使用声明；公开发布前需再确认署名要求。
